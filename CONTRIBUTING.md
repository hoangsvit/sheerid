# Contributing

Contributions that improve the safety, accessibility, reliability and documentation of authorized verification workflows are welcome.

1. Open an issue describing the problem or feature; avoid sharing real student information or live verification links.
2. Use a branch for the change and keep the scope small.
3. Run `npm ci` and `npm test`. Install Camoufox to run browser-specific tests locally when relevant.
4. Describe the change, tests performed, and any compatibility considerations in a pull request.

Prefer clear English UI strings and documentation. Keep credentials, personal data, uploaded documents and task artifacts out of commits. Do not submit changes designed to bypass eligibility controls or human verification.
